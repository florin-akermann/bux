# L0606 — an archive that a `jar` line names is not there

A `jar` line names a Java archive that is on disk already, and this file is not there.

```text
package shapes
version 0.2.0
jar lib/geometry.jar sha256:4f2c000000000000000000000000000000000000000000000000000000009a1e
```

The path is read against the directory of the package, so `lib/geometry.jar` is below it.
Nothing is fetched, so an archive that is not on disk is an archive that a run cannot reach.

## What to do

Put the archive at the path that the line states.
Or change the path of the line to the place of the archive.

## When it is raised

`bux build`, `bux run`, and `bux test` raise it before they write a class.
The diagnostic points at the `jar` line in `bux.package`.
A build stops at the first archive that is refused.
`docs/specs/packages.md` states the `jar` line and each refusal.
