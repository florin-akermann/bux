# L0610 — the directory of the module holds `:`, which splits the class path

A class path puts a `:` between two paths, so a path that holds a `:` is read as two paths.

```text
bux run build:old/main.bx
```

`bux run` puts `build:old/target` on the class path, which a JVM reads as `build` and `old/target`.
The classes are in neither, so the run would reach a directory that no manifest names.
So the module is refused before anything is compiled, whatever text the file holds.
The diagnostic points at the start of the file, because the directory is what is wrong.

`bux test` writes its classes into a directory of its own, so it puts no `target/` on a class path.
It puts each archive that `bux.package` states there, read against the same directory.
So `bux test` refuses the module, or the package, only where it reaches an archive.

## What to do

Move the module, or its package, to a directory whose path holds no `:`.
A path that the command names relative to the current directory holds only what is written.

## When it is raised

`bux run` raises it for a module, and `bux test` for a module or a package that reaches an archive.
`bux build` and `bux check` put nothing on a class path, and they do not raise it.
A `:` in a `depends` or a `jar` path of `bux.package` is `L0315`, for the same reason.
`docs/specs/run.md` states the class path.
