# L0604 — a run of the examples reaches a name the module declares

`bux test` runs the examples a module states by writing a module around them.

That module writes a line about each example that did not hold, and `io.println` is the one way
there is to write a line, so the module the run writes opens with `import io`.
A module declares each name once, so a module that declares `io` of its own leaves the run no
room:

```
// example: is_ready(io(3))
fn is_ready(count: Int) -> Bool {
    count > 0
}

// example: io(3) == 3
fn io(count: Int) -> Int {
    count
}
```

`bux check`, `bux build`, and `bux run` all accept this module.
Only `bux test` refuses it, and only because of how a run is put together.

The `main` that module writes takes the words a program is run with, under the name `arguments`.
A module that declares `arguments` at the top level is refused here the same way, and for the
same reason.

## What to do

Call the declaration something else.

A module named `io` is one the library carries, `docs/specs/io.md` says what it declares, and a
declaration sharing that name is one nothing in the module can reach past anyway.

A module whose examples are not run is otherwise unaffected: `bux build` and `bux run` take
it as they always did.

## When it is raised

`bux test` raises it, and no other command does.

It is raised before anything is compiled, so it is the whole of what a run says: there is no
module to run, and no example of it has an answer yet.
