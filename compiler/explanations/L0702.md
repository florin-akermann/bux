# L0702 — two parts of one program have one name

The compiler writes the classes of a module under the name of the module.
Two modules with one name can write two different classes under one name.
One file holds one class, so one of the two would be lost, and a call into it would reach the other.
So the compiler refuses the program and points at the module that it loaded last.

A part is a module of the program, or the library that the compiler carries.
A module named `bux` has the name of the classes of the library, such as the class of a list.
Then the program and the library can write two different classes under one name.
A module that has the name of a module of the library, such as `strings`, does not clash.
The class of a module of the library is in the package `bux/library`, and the other is not.

Two modules that write the same class, such as the class of a list, do not clash.
The compiler writes that class once.

## Names that differ only in case

The types `Setup` and `SetUp` of the module `main` have the classes `main/Setup` and `main/SetUp`.
A disk that ignores case, as a Mac and Windows do by default, holds the two as one file.
So the two types clash, although their names are not equal.
The compiler refuses such a pair on every disk, so that a build gives one answer everywhere.
It compares the ASCII letters only, and a letter outside ASCII keeps its case.
The message names the module that owns the class, and it shows the two names as each is spelled.

## What to do

Rename this module, so that no other part of the program has its name.
Then change each `import` of it to the new name.
For two names that differ only in case, rename one of them, so that they differ in more than case.

## When it is raised

`bux build`, `bux run`, and `bux test` raise it when they write the classes of a program.
`bux check` writes no class, so it does not raise it.
