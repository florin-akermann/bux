# L0702 — two parts of one program have one name

The compiler writes the classes of a module under the name of the module.
Two modules with one name can write two different classes under one name.
One file holds one class, so one of the two would be lost, and a call into it would reach the other.
So the compiler refuses the program and points at the module that it loaded last.

A part is a module of the program, or the library that the compiler carries.
A module named `lumen` has the name of the classes of the library, such as the class of a list.
Then the program and the library can write two different classes under one name.
A module that has the name of a module of the library, such as `strings`, does not clash.
The class of a module of the library is in the package `lumen/library`, and the other is not.

Two modules that write the same class, such as the class of a list, do not clash.
The compiler writes that class once.

## What to do

Rename this module, so that no other part of the program has its name.
Then change each `import` of it to the new name.

## When it is raised

`lumen build`, `lumen run`, and `lumen test` raise it when they write the classes of a program.
`lumen check` writes no class, so it does not raise it.
