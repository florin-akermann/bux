# L0409 — a call must name its arguments

A call passes its arguments in order, and the types usually hold them apart.

```
fn rename(from: String, to: String) -> String {
    from + to
}
```

Here they do not.
`rename(old, new)` and `rename(new, old)` both have the types the declaration asks for.
One of them is wrong.
The mistake shows up when the program runs, or never.

Where the declaration gives two of its parameters one type, the call says which is which:

```
rename(from: old, to: new)
```

A name is written before its value and joined by `:`, exactly as a record writes a field.
The names run in the order the declaration lists the parameters.
Naming reorders nothing; it says what the order already is.
A swapped pair is then refused where it is written rather than read as the wrong answer.

A call names all of its arguments or none of them.
Where the parameter types all differ, either way is allowed and the choice is the author's.

The types compared are the ones the signature writes, which every function writes whole.
A type parameter counts as a type, so `fn pair<T>(first: T, second: T)` repeats one.

A constructor is not reached by this rule.
`Span(0, 10)` carries its values in order and has no names to write.
A variant whose values want names declares them as fields and is built as a record.
