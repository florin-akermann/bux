# L0314 — a name that binds is written inside an or-pattern

`A | B` matches what `A` matches and what `B` matches, and it binds nothing at all.

```text
match status {
    Failed(reason) | Cancelled(reason) => reason
    Done => "done"
}
```

`reason` binds, so this is refused where the first one is written.

An or-pattern that binds a name must bind the same names at the same types in each alternative.
That is a rule about the set of alternatives, not about each of them.
No example in hand asks for that machinery.
`docs/specs/patterns.md` states the rule and why it is the narrow one.

The arms it would have saved are written as one arm each:

```text
match status {
    Failed(reason) => reason
    Cancelled(reason) => reason
    Done => "done"
}
```

A pattern that binds nothing is written inside an or-pattern as freely as anywhere else.
A variant that carries nothing, a literal, and `_` each bind nothing.
So `Pending | Running` and `0 | 1` are both written.
A record pattern binds every field it names, so only `P {}`, which names none, is an alternative.
