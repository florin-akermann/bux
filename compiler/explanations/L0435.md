# L0435 — a foreign reference escapes the function that reaches it

A value of an `extern` type is a foreign reference, and it stays in the function that reaches it.

```
fn opened(path: String) -> File {
    named(path)
}

extern new named(path: String) -> File

extern type File = "java.io.File"
```

`File` names a Java object, which has identity and can change.
A function that gave one back would share that object with every caller that keeps it.
A field would share it with every value that holds the record, for as long as the record lives.

A foreign reference can go to four places, and to no other place.
An `extern` declaration reaches it.
A `let`, a `var`, a parameter, a `match` arm, or a `for` binds it.
A call takes it as an argument.
`?` and `match` read it where it is.

These places are refused:

- the result of a function that the program declares, where it is or holds an `extern` type;
- a field of a record, or a position of a variant, that is or holds an `extern` type;
- a call of a function or a constructor that gives one back through a type parameter.

For `fn same<T>(value: T) -> T`, the third place is `same(file)`.
It is also `Some(file)`, and `Box { value: file }` for `type Box<T> = { value: T }`.
A call of an `extern` declaration is not refused, because that call reaches the reference.

## What to do

Keep the foreign reference in the function that reaches it, and give back or hold a value.
A path, a count, or a line of text is a value.
A function that needs the Java object takes it as an argument, and gives back what it found.
A function that changes the object in place gives back `()`, and the caller keeps its own binding.
