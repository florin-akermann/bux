# L0202 — a name is not written in canonical case

There is one way to spell a name, and the compiler writes it.

A function, a parameter, a record field, and an imported module are `snake_case`:

```
fn count_active(users: List<User>) -> Int {
```

A type, a variant, and a type parameter are `PascalCase`:

```
type UserId = UserId(Int)
```

`snake_case` is lowercase letters and digits with `_` between words.
A name neither begins nor ends with `_`, and never writes two in a row.

`PascalCase` is words run together, each beginning with one uppercase letter.

## An acronym is a word

`UserID` does not compile, and `UserId` does.

Two uppercase letters never stand next to each other in `PascalCase`, which is the same rule said
the other way.
An acronym spelled in capitals runs into whatever follows it: `HTTPServer` hides where one word
ends and the next begins, and `HttpServer` does not.

The help prints the canonical spelling of the name you wrote, so the fix is to write that.

`docs/specs/naming.md` states the rules.
