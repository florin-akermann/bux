# L0436 — a function leaves a type out of its signature

Every function writes the type of each parameter and the type of its result.

```
fn doubled(count) -> Int {
    count + count
}
```

```text
error[L0436]: `count` of `doubled` states no type, and a function writes its whole signature
help: write the signature `fn doubled(count: Int) -> Int`
```

A caller reads the signature, and so does the page that `bux api` prints.
A type that only the body settles makes the reader open the body.
An error then shows at a distant call, and not in the body that caused it.

The rule holds for a function of a module, a method of an `instance`, and a method of a `trait`.
It holds for `start` and `receive` of a `process` too, where `L0806` refuses a type left out first.
Inference still works inside a body, so a `let` or a `var` writes no type.
A test is no function, and it writes no signature.

A function that gives back nothing of interest writes `-> ()`:

```
fn greet(name: String) -> () {
    io.println("hello, " + name)
}
```

## What to do

Write the signature that the help gives.
The compiler infers the body first, so the help spells the types that inference settled.
A `_` in the help is a type that nothing settled; choose the type that the function means.
