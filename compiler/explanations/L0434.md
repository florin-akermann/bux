# L0434 — an `extern` names a class that the build cannot account for

An `extern` declaration names one member of one Java class.
The build accepts the class only where it can say where the class comes from.

```text
extern static class_named(name: String) -> Result<Loaded, String> = "java.lang.Class.forName"
```

A class comes from one of two places.
It is in an archive that a `jar` line of the manifest states, with its hash.
Or it is a class of `java.base` on a fixed list, which `docs/specs/interop.md` states.
`java.lang.Class` is in neither place, so this declaration is refused.

The list leaves out reflection, class loaders, handles to members, and deserialization.
Each of those reaches code by a name that the program holds only at run time.
No reader of the program text can see that code, so no reader can check it.
A class of a JDK module other than `java.base`, such as `javax.naming.InitialContext`, is out too.

The list also leaves out a few members of classes that are on it, such as `System.load`.
A declaration that names one of those members is refused with this code too.

A program cannot add to the list, and a manifest cannot add to it.
A class that a program needs and that is not on the list comes from an archive.
Put the archive in the package, and state it with a `jar` line.
An archive does not account for a class in a package of the JDK, such as `java.lang.reflect`.
The JVM loads that class from the JDK and not from the archive.
`docs/specs/packages.md` states the `jar` line.
