# L0304 — a name that is not a value is written as one

A function and a module are each reached one way, and neither is a value.

## A function is reached by calling it

```
fn go(users: List<User>) -> List<User> {
    filter(users, is_active)
}
```

`is_active` here is a function handed to another function rather than called.
That is where the language is going, and `docs/design.md` section 11 shows it.
Version 0.1 has no type and no shape for a function held as a value, so there is nothing to hand.

A function name is written with its arguments:

```
fn go(user: User) -> Bool {
    is_active(user)
}
```

Binding one is the same: `held := helper` names a function, and `helper()` is what was meant.

## A module is reached through

```
import io

fn go() -> Int {
    held := io
    1
}
```

`io` names a module, which is what a name is reached through rather than something to hold.
`io.println` is how one is written, with the `.` and the name inside it.

## A function of a module is reached by calling it too

```
import demo

fn go() -> Int {
    held := demo.helper
    1
}
```

`demo.helper` names a function of another module, which is no more a value than one of this file.

A variant that module declares is a value, and one carrying nothing is written as the name alone:

```
import demo

fn go() -> demo.Payment {
    demo.Pending
}
```

Which of the two a name is depends on what the other module declares, so inference raises this
one rather than name resolution.

The refusal is the front end's rather than code generation's.
A program with no way to be compiled is then refused where it is written.
