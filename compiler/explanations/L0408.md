# L0408 — a value is left with nothing to take it

A statement written for its effect has nothing to leave behind, so its type is `()`.
A statement that leaves something else behind has worked a value out that nothing reads.

```
fn stored(user: User) -> () {
    save(user)
}
```

`save` gives back a `Result<(), Error>`, and this line drops it.
Lumen has no exceptions, so a failure is a value rather than an event.
A dropped value is then a swallowed failure, and the one way such a program can still lose one.

The last statement of a block is the block's value, so it is not refused here.
Everything above it is, and so is the last statement of a `for` body, which nothing takes either.

Where the value matters, read it:

```
fn stored(user: User) -> Result<(), Error> {
    save(user)?
}
```

Where it does not, say so:

```
fn stored(user: User) -> () {
    _ = save(user)
}
```

`_ = ` throws the value away on purpose, and the line says that is what was meant.
`_` is not a name and binds nothing: it is written on the left of a single `=` and nowhere else.
A reader asking what a function ignores greps for `_ =` and finds every one of them.
