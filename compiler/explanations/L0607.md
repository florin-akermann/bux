# L0607 — an archive has a hash other than the hash that its line states

A `jar` line pins the bytes of an archive with a hash, and this file has other bytes.

```text
package shapes
version 0.2.0
jar lib/geometry.jar sha256:4f2c000000000000000000000000000000000000000000000000000000009a1e
```

The hash is the SHA-256 of the bytes of the file, as `sha256:` and 64 lowercase hexadecimal digits.
The diagnostic shows the hash that the file has, so the reader sees both hashes.
A run reaches only the bytes that the manifest states, so a changed archive is refused.

## What to do

Find out why the archive changed.
If the archive is the one that the package uses, write its hash in the line.
`shasum -a 256 lib/geometry.jar` shows the same hash.

## When it is raised

`bux build`, `bux run`, and `bux test` raise it before they write a class.
The diagnostic points at the `jar` line in `bux.package`.
A build stops at the first archive that is refused.
`docs/specs/packages.md` states the `jar` line and each refusal.
