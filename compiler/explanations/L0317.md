# L0317 — one module name, two files

An import names a module, and two files both claim that name.

```text
package app
version 0.2.0
depends ../shapes
depends ../colours
```

`import circle` is refused where `../shapes/circle.bx` and `../colours/circle.bx` both exist.

It is refused the same way where this package holds `circle.bx` of its own and something has
already reached `../shapes/circle.bx`.
A module beside the importing file is what that import reaches, and the dependencies are not
consulted at all; what is refused is one build holding two modules of one name.

One name has one definition, which `docs/design.md` section 16 states.
Picking one of the two would make which definition a name means depend on the order the files
were reached in, and a reader would have to know that order to know what they are reading.

A module the library carries is not a clash, because it is reached before any file is.
Two routes to one file are not a clash either: a package two packages both depend on is reached
through each of them and read once.

The answer is to rename one of the two modules, or to stop depending on one of the two packages.

`docs/specs/packages.md` states the order an import is answered in.
