# L0415 — a type holds a value of itself

A record has a field whose type is the record itself, or a ring of records comes back round.

A Bux value has no null, so that field would hold a whole value of the type.
Its own field would hold another, and there is no end to it and no first one to build.
The declaration is refused rather than a program that builds one, because nothing can build one.

```text
type Node = {
    number: Int
    next: Node
}
```

A ring of declarations is refused the same way, so an `A` holding a `B` that holds an `A` is too.
The error names the ring it found, in the order it runs.

`Option` is how a type holds another of its own kind:

```text
type Node = {
    number: Int
    next: Option<Node>
}
```

`None` is where the chain stops, and a `Node` is then a value that can be built.

A field written as the base of an algebraic data type is not a ring either.
Such a field holds whichever variant it was handed, so what sits there is a reference.
