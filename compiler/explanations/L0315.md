# L0315 — a manifest is not written the way a manifest is written

A package is a directory of modules, and `bux.package` beside them is what names it.

```text
package shapes
version 0.2.0
depends ../geometry
```

Every line is a keyword, one space, and one word.
`package` is written first and `version` second.
A `depends` line for each dependency comes after both.
There is one way to write a manifest, so a line out of that order is refused.
A keyword that is none of the four, a missing word, and a word that holds a space are refused.
A directory that two `depends` lines both name is refused too.

A path that a `depends` states is read against the directory of the manifest.
So `../geometry` is a sibling of that directory.
Nothing is fetched: the directory is already there, or `L0316` says it is not.

The name and the version are stated, and nothing reads either yet.
A manifest that leaves one out is refused all the same.
A package says what it is before anything asks, and the version that resolves is the one fetched.

A `jar` line comes after every `depends` line, and names a Java archive by its path and hash.

```text
jar lib/geometry.jar sha256:4f2c000000000000000000000000000000000000000000000000000000009a1e
```

The hash is `sha256:` and 64 lowercase hexadecimal digits, and a line with another hash is refused.
A path that holds a blank or a `*` is refused too.
A `depends` or `jar` path that holds a `:` is refused, because a class path reads it as two paths.
A manifest states one `jar` line for each archive, so a second line with one path is refused.

`docs/specs/packages.md` states the manifest line by line.
