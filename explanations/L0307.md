# L0307 — a ring of imports

Two or more modules import each other, around a ring that comes back to where it started.
A module that imports itself is the smallest ring, and it is refused the same way.

A module is compiled after every module it imports.
Each name it reaches through an import has a type before the module that uses it is checked.
A ring leaves no such order: each module in it waits on the next, and the last waits on the first.

```text
// main.bx
import greeting

fn main(arguments: List<String>) -> Int {
    greeting.hello()
    0
}
```

```text
// greeting.bx
import main

fn hello() -> () {
    main.start()
}
```

Neither can be compiled first, so the ring is refused at the import that closes it.

This is unlike two declarations within one module, which are written either way.
`docs/specs/modules.md` says why: a module is resolved whole, so nothing inside it waits.

Move what both modules need into a module they both import, which is compiled before either.
