# L0317 — one module name, two files

An import names a module, and two files both claim that name.

```text
package app
version 0.2.0
depends ../shapes
depends ../colours
```

`import circle` is refused where `../shapes/src/circle.bx` and `../colours/src/circle.bx` exist.

It is refused the same way where this package holds `src/circle.bx` of its own.
That is so where something already reached `../shapes/src/circle.bx`.
A module beside the importing file is what that import reaches, and no dependency is looked in.
What is refused is one build that holds two modules of one name.

A test module `tests/circle.bx` and a module `src/circle.bx` of one package clash the same way.

One name has one definition, which `docs/design.md` section 16 states.
To pick one of the two makes the meaning of a name depend on the order the files were reached in.
A reader then has to know that order to know what they read.

A module the library carries is not a clash, because it is reached before any file is.
Two routes to one file are not a clash either.
A package that two packages both depend on is reached through each of them, and is read once.

The answer is to rename one of the two modules, or to stop depending on one of the two packages.

`docs/specs/packages.md` states the order an import is answered in.
