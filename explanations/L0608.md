# L0608 — the manifest of an archive names more archives

The manifest of this Java archive has a `Class-Path`, and a JVM reaches each archive it names.

```text
package shapes
version 0.2.0
jar lib/geometry.jar sha256:4f2c000000000000000000000000000000000000000000000000000000009a1e
```

A run reaches only the archives that `bux.package` states, and nothing else.
An archive with a `Class-Path` would put archives on the class path that no line states.
So the archive is refused whatever its `Class-Path` holds, even when it holds nothing.

## What to do

Use an archive whose `META-INF/MANIFEST.MF` has no `Class-Path`.
Write a `jar` line for each archive that it named, each with its own hash.

## When it is raised

`bux build`, `bux run`, and `bux test` raise it before they write a class.
The diagnostic points at the `jar` line in `bux.package`.
A build stops at the first archive that is refused.
`docs/specs/packages.md` states the `jar` line and each refusal.
