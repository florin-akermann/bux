# L0433 — a call is written with its first argument in front of the name

A function is called one way: its name, then every argument inside the parentheses.

```
fn described(count: Int, said: String) -> String {
    shown(count) + " " + said
}
```

`count.described("apples")` puts `count` in front of the name, and a dot does not do that.
A dot reads a field of a record, as `user.name` does.
A dot after a module reaches a function of that module, as `io.println("hi")` does.
`count` is a value and not a module, so the dot after it calls nothing.

The call is written plainly:

```
described(count, "apples")
```

The `help:` line shows the plain call, with the value that was in front as the first argument.
Where the call names its arguments, the value is named for the first parameter.
`old.rename(to: new)` is then written `rename(from: old, to: new)`.

A second spelling of one call is a cost with no guarantee behind it.
With one spelling, the name alone says which function is called, before any type is known.
