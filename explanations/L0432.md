# L0432 — an `Option` carries `()`

A program writes `Option<()>`, or inference gives an expression a type that holds one.

`Some(())` says only that a value is there, and `None` says that it is not.
That is `Bool` written a second way, and one thing has one way to write it.
At the boundary to the platform it is also a flag for a `null`, and Bux has no null.

```text
fn is_saved() -> Option<()> {
    Some(())
}
```

A written `Option<()>` is refused where the signature, the field, or the `extern` writes it.
An inferred one is refused at the innermost expression whose type holds it.
So `Some(())`, a `None` that meets an `Option<()>`, and a call of a generic are each refused.
The call of `fn first<T>(items: List<T>) -> Option<T>` over a `List<()>` is an example.

Where only the answer "yes" or "no" is given, give back a `Bool`:

```text
fn is_saved() -> Bool {
    true
}
```

Where a failure has a reason to give, give back a `Result`, whose `Err` carries that reason:

```text
fn saved() -> Result<(), String> {
    Ok(())
}
```

`Result<(), E>` stays, because the caller could not work out what its `Err` holds.
`docs/rationale.md` section 5 says why, and `docs/specs/types.md` states the refusal.
