# L0501 — a `match` lists its arms out of order

A `match` lists its arms in the order the type declares its variants.

```text
error[L0501]: this `match` writes `Pending` after `Failed`
```

A new variant then has exactly one place to be handled.
Adding one is never a diff that also moves the arms already written.

```text
fn describe(payment: Payment) -> String {
    match payment {
        Pending => "waiting"
        Failed(reason) => reason
    }
}

type Payment =
    | Pending
    | Failed(String)
```

An arm is placed by the constructors it writes, outermost first.
Two arms that reach inside one variant are placed by what they reach for.

An arm that names no variant — a name that binds, a number, a string — is not placed at all.
It is written where the author put it, because what it covers is no one variant's position.
