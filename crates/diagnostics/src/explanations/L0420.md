# L0420 — a whole number does not fit the type it is written at

A whole-number literal takes the type its context expects, which `docs/specs/literals.md` states,
and the type it lands on says which whole numbers it holds.

```text
error[L0420]: `5000000000` does not fit `Int32`, which holds `-2147483648` to `2147483647`
```

The range is not the machine's; it is what the author of the type claimed.
`instance IntegerLiteral<Int32>` writes `lowest` and `highest`, and those two bodies are the range
every literal at `Int32` is held to.

There are two answers, and which one is right is about the type rather than about this line.
Write a whole number the type holds, if the value here was a slip.
Widen what the instance says it holds, if the type was always meant to reach this far.

Nothing is wrapped and nothing fails at run time, because a literal is no exception: a number
that does not fit is refused where a reader can see both the number and the type.
