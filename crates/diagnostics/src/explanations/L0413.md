# L0413 — a `Bool` function is named for a command

A function whose result is `Bool` answers a question, and its name asks one.

```
fn active(user: User) -> Bool {
    user.active
}
```

`active(user)` reads as a command at every call site.
`if active(user)` reads as though something is being activated, which is not what it does.

Begin the name with `is_`, `has_`, `can_`, or `should_`:

```
fn is_active(user: User) -> Bool {
    user.active
}
```

`if is_active(user)` reads as the question it is.

Four prefixes cover the questions a program asks.
A name that needs a fifth is a name answering more than one question, and it is two functions.

## The result read is the one inference settled

A function that writes no result type is held to whatever type it turned out to have.
That is the same reading the flag rule of `docs/specs/arguments.md` gives a signature, and for the
same reason: a signature the author left unwritten counts exactly as one they wrote out.

`docs/specs/naming.md` states the rules.
