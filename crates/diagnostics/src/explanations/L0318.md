# L0318: an instance writes an argument that is no type parameter of its own

An instance is for one type, and a type written with arguments gets one instance that answers at
every argument.
So the arguments are the type parameters the instance declares, and the instance answers for all
of them at once.

```text
instance Eq<Box<Int>> {
    fn is_equal(one: Box<Int>, other: Box<Int>) -> Bool {
        true
    }
}
```

`Int` is a type rather than a parameter, so this instance would answer for `Box<Int>` and leave
`Box<Bool>` with none.
One trait and one type have one instance, and `Box` is the type here, so there is no second
instance to write for the rest.

Declare the parameter and write the instance over it:

```text
instance<T: Eq<T>> Eq<Box<T>> {
    fn is_equal(one: Box<T>, other: Box<T>) -> Bool {
        true
    }
}
```

The constraint is what lets the body compare two values of `T`, exactly as a constrained generic
function's does.

`docs/specs/traits.md` states how an instance is written for a type written with type parameters.
