# L0425 — that type does not cross the boundary

An `extern` signature says what the Java member it names takes and gives back.
Every type in it compiles to the JVM type the member's own descriptor holds.
Only the types that have one may be written.

```text
extern static read_string(path: Path) -> String = "java.nio.file.Files.readString"
```

`Bool`, `Int`, `String`, and a type an `extern type` declares each cross, in either place.
`()`, `Option<T>`, and `Result<T, String>` are results and never parameters.
`List<T>` is the other way round: a member takes a `java.util.List` copy of what the list holds.
A member takes one, and no member gives one back: a list something else can change is no value.
A `field` is read rather than called, and the JVM has no field of type `void`.
`()` is therefore no result for a `field`: a field holds a value, or it is no field.

A record, a variant, and a type parameter are Lumen types a Java member has no descriptor for.
Each of them is refused here.
There is no subtyping and no widening at the boundary.
A member that takes `java.lang.Object` is therefore not reachable either.
The answer is to name a member that takes what the caller already holds.

`docs/specs/interop.md` lists what crosses and why the list is that short.
