# L0425 — that type does not cross the boundary

An `extern` signature says what the Java member it names takes and gives back.
Every type in it compiles to exactly the JVM type the member's own descriptor holds, so only the
types that have one may be written.

```text
extern static read_string(path: Path) -> String = "java.nio.file.Files.readString"
```

`Bool`, `Int`, `String`, and a type an `extern type` declares each cross, in either place.
`()`, `Option<T>`, and `Result<T, String>` are results and never parameters.
A `field` is read rather than called, and the JVM has no field of type `void`, so `()` is no
result for one of those: a field holds a value or it is no field.

A `List`, a record, a variant, and a type parameter are Lumen types a Java member has no
descriptor for, and each is refused here.
There is no subtyping and no widening at the boundary, so a member taking `java.lang.Object` is
not reachable either, and the answer is to name one that takes what the caller holds.

`docs/specs/interop.md` lists what crosses and why the list is that short.
