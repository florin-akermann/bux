# L0312: a derive names something no derive is written for

A `derive` asks the compiler to write an instance, and the compiler writes the instances it knows
how to write, for the types whose declarations it can read.

## A trait no type derives

`Eq`, `Ord`, `Hash`, and `Show` are the four, and each answers by reading what a value holds,
which leaves the author nothing to decide.

```text
derive Add for User
```

`Add` builds a value out of two, and what adding two records amounts to is a decision about the
type rather than a reading of it, so it is not one the compiler makes on the author's behalf.

Write the instance by hand:

```text
instance Add<User> {
    fn add(one: User, other: User) -> User {
        User { id: one.id + other.id }
    }
}
```

## A type this module does not declare

```text
derive Eq for Int
```

What a derive writes follows from the declaration it names, so the declaration has to be in this
module to be read.
A prelude type has the instances the prelude ships and no others.

`docs/specs/derive.md` states which traits a type derives.
