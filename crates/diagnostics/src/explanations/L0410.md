# L0410 — an argument is named for the wrong parameter

A named call still passes its arguments in order.
The names say which order that is, so they run in the order the declaration lists them.

```
fn rename(from: String, to: String) -> String {
    from + to
}
```

```
rename(to: new, from: old)
```

The first argument is passed for `from` and is named `to`, so the call is refused.
Written the other way round it compiles:

```
rename(from: old, to: new)
```

Naming is not a way to reorder a call.
A call that reads better another way round is a sign the declaration lists its parameters wrongly.
The declaration is where that is fixed.

An argument named for a parameter the declaration does not have is refused here too.
Every name in a call is one of the declaration's, in the place the declaration gives it.
