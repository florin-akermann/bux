# L0431 — a narrowed argument has no `None` to be said with

`Int` compiles to a `long`, and a great many Java members take an `int` instead.
A parameter written `int` says so, and the argument is narrowed to an `int` before the member is
reached.

```text
extern method char at(text: String, int index: Int) -> Int = "charAt"
```

Narrowing a `long` to an `int` loses whatever does not fit, and nothing in Bux is partial.
An argument outside the `int` range therefore has an answer of its own, and a result of `Int`
leaves nowhere to put it.
The answer is to give back an `Option`:

```text
extern method char at(text: String, int index: Int) -> Option<Int> = "charAt"
```

Each narrowed argument is compared with the `int` range before the member is reached.
If any argument is outside it, the answer is `None` and the member is not reached at all.
Otherwise each argument becomes an `int`, the member is called, and the answer is `Some` of what
it gave back.

`Option<Int>` is a result of such a declaration, and so is `Option<T>` for every other `T` that
crosses the boundary as a value.
A declaration that narrows no parameter keeps the rule it always had: an `Option` over a number
is `L0425`, because a number is never `null`.

`()` is the one result this has no answer for.
A member that gives nothing back has nothing for a `Some` to hold, and `Option<()>` is refused
with `L0425`, so a `void` member that takes an `int` is not reachable in version 0.1.

`Result<Option<T>, String>` composes as it always did.
The guard is outside, so an argument that does not fit is `Ok(None)`.
Where the result is a reference, a `None` still also reads a `null` the member gave back.

`docs/specs/interop.md` states the narrowing and what it asks of the result.
