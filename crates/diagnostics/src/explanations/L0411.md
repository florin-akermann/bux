# L0411 — a call names arguments that have no names

A call names its arguments by naming the parameters they are passed for.

```
fn rename(from: String, to: String) -> String {
    from + to
}
```

`rename(from: old, to: new)` works because `rename` is declared here, with those parameter names.
Two things a call reaches have no such names, and naming their arguments is refused.

A constructor is the first.

```
type Range = Range(Int, Int)
```

`Range(start: 0, len: 10)` looks as though `start` and `len` say where each value lands.
They do not: a constructor carries its values in order and has nothing to check the names against.
Writing them would read as a promise the compiler cannot keep.
A variant whose values want names declares them as fields:

```
type Range = { start: Int, len: Int }
```

That is built `Range { start: 0, len: 10 }`, and the names are the fields'.

The prelude is the second.
`or` and `todo` are supplied rather than declared here, so no parameter names hold a call to them.
`or(value: found, fallback: 0)` is refused for that reason.
Their parameters have different types, so no call of either is ever asked to name one.
