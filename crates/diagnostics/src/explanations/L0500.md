# L0500 — a `match` does not cover every value

A `match` answers for every value of the type it matches.
One that leaves a value unanswered would have nothing to evaluate when it met that value, and the
language has no answer to supply on the author's behalf.

The refusal names a value that is not covered, written in the shape of an arm that would cover it.
`_` stands there for any value; an arm writes a name of its own in its place.

```text
error[L0500]: this `match` does not cover `Failed(_)`
```

Write an arm for it, or a name, which binds whatever the arms before it did not.

```text
match payment {
    Pending => "waiting"
    other => "something else"
}
```

This is what makes a variant safe to add.
Adding one to a type points the compiler at every match that has not been told what to do with it.
None is left to be found at run time.
