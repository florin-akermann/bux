# L0422: a type derives `Eq` and something it holds has none

A derived `Eq` compares a value field by field, and each field is compared by the `Eq` of its own
type.
A field whose type has no instance leaves the derived one nothing to call, so the derive is refused
naming the field.

```text
derive Eq for User

type User = {
    id: Int
    tags: List<Int>
}
```

`List<Int>` is written with an argument, and `docs/specs/traits.md` gives an instance to a type
written by name, so `List<Int>` has no `Eq` to reach.

Give the held type one, or hold a type that has one:

```text
derive Eq for User

type User = {
    id: Int
    name: String
}
```

A field whose type derives `Eq` further down the file counts, so two types that hold each other
derive `Eq` together.
