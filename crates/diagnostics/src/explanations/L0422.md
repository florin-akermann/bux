# L0422: a type derives a trait and something it holds has no instance of it

A derived instance reads a value field by field, and each field is handed to the instance of its
own type.
A field whose type has none leaves the derived one nothing to call, so the derive is refused
naming the trait and the field.

```text
derive Hash for User

type User = {
    id: Int
    tags: List<Int>
}
```

`List<Int>` is written with an argument, and `docs/specs/traits.md` gives an instance to a type
written by name, so `List<Int>` has no `Hash` to reach.

Give the held type one, or hold a type that has one:

```text
derive Hash for User

type User = {
    id: Int
    name: String
}
```

A field whose type derives the same trait further down the file counts, so two types that hold
each other derive it together.
