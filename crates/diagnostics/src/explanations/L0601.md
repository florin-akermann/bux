# L0601 — a function states no example

Every function a module declares at the top level states at least one example:

```
// Divides `total` among `people`, giving back nothing where there is nobody to divide among.
//
// example: or(shared(total: 17, people: 5), 0) == 3
fn shared(total: Int, people: Int) -> Option<Int> {
    total / people
}
```

An example is a line of the comment above the function.
It is the marker, the word `example`, a colon, and one Lumen expression of type `Bool`.
`lumen test` runs every example a module states, so a stale one is a failing test.

A signature says what a function takes and gives back, and says nothing about what it does.
Prose says that and drifts, because nothing runs prose.

`main` states none, because it is reached by running the module rather than by calling it.

## What to do

Write one example above the function, stating a case worth stating.

An expression that is not `true` is a failing example rather than a refused one.
`lumen test` is what says so.

The example need not name the function it is written above.
Nothing can call a function whose argument version 0.1 has no way to write.
There is nothing to state about such a function, and `// example: true` states that much.
It goes away when the value it cannot write becomes writable.

## When it is raised

`lumen build`, `lumen run`, and `lumen test` raise it; `lumen check` and `lumen fmt` do not.

An example is written around the function it documents, so the function is written first.
A check that refused a function without one would refuse the state every function passes through.

Every function that states none is named, rather than the first.
A build is how a reader learns what is left, and a list of one would not be that list.
