# L0417 — a generic function is reached through a module

A name was reached inside a module, and the function found there is generic.

A generic function is written once per set of types it is used at, which
`docs/specs/codegen.md` states.
The module declaring it is what writes those, and it writes the ones its own body reaches.
A module importing it would reach a set of types that module never wrote.

```text
// holding.lm
fn held<T>(value: T) -> T {
    value
}
```

```text
// main.lm
import holding

fn main() -> () {
    _ = holding.held(1)
    ()
}
```

`holding` writes `held` at whatever types `holding` itself uses, and `Int` need not be one.

A function is generic by the type inference settled on it rather than by what it wrote, so one
writing no type parameter at all is refused the same way when nothing settled its type:

```text
// holding.lm
fn held(value) {
    value
}
```

Nothing there says what `value` is, so `held` is written per set of types just as `held<T>` is.

The answer in version 0.1 is a signature at one set of types, which the importing module can then
name, or the generic written in the module that reaches it.
