# L0309 — an instance does not write the methods its trait declares

An instance writes a body for every method its trait declares, once, and for no other name.

```text
error[L0309]: `Eq` declares `is_equal`, which this instance does not write
```

A method left out would leave a call with nothing to reach, and a name the trait never declared
would be a function nothing can call: an instance declares no name of its own.
A name written twice is the same reason again, from the other side: one of the two bodies would be
reached and the other lost.

The trait's declaration says what to write:

```
trait Eq<T> {
    fn is_equal(one: T, other: T) -> Bool
}

instance Eq<Point> {
    fn is_equal(one: Point, other: Point) -> Bool {
        one.across == other.across && one.down == other.down
    }
}
```

A body may leave the types out and let inference read them off the trait, so
`fn is_equal(one, other)` writes the same instance more shortly.
