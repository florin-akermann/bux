# L0424 — a generic of another module is used at a type whose instance stays in a module

A generic is written once per set of types it is used at, by the module that declares it.
`docs/specs/codegen.md` states that, so a use in another module asks that module for the method.
The body that module writes is its own, and every name it reaches, it reaches from where it sits.

A trait and its instances stay where they are declared, which `docs/specs/modules.md` states.
Neither module offers the other its instances, so the prelude's are the only ones both are sure of.
A constraint written over a type parameter is answered there, and at no other type.

```lumen
import io

import list

fn main() -> () {
    if list.has_value([Kept("a")], Kept("a")) {
        io.println("kept")
    }
}

derive Eq for Kept

type Kept = Kept(String)
```

`list.has_value` is `fn has_value<T: Eq<T>>(values: List<T>, value: T) -> Bool`.
Its body compares two values of `T`, so the instance answering `Eq` is one `list` itself reaches.
This use settles `T` on `Kept`, whose `Eq` this module derives and `list` cannot name.

An instance the other module declares is refused from the other side for the same reason.
A module offers the names a reader writes, and an instance has none, so this one cannot know of it.

Write the loop where the instance is:

```lumen
fn has_kept(values: List<Kept>, value: Kept) -> Bool {
    for held in values {
        if held == value {
            return true
        }
    }
    false
}
```

Or call it at a type the prelude has the instance for:

```lumen
if list.has_value(["a", "b"], "a") {
    io.println("the words hold a")
}
```

A generic whose type parameters carry no constraint is reached at any type at all.
Nothing in such a body asks for an instance, so nothing has to be reached from the other module.
