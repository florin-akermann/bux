# L0424 — a generic of another module is constrained by a trait that stays in that module

A generic is written once per set of types it is used at, by the module that declares it.
`docs/specs/codegen.md` states that, so a use in another module asks that module for the method.
A constraint the declaration writes over a type parameter is answered by the instance the type
settled on has, wherever that type is declared, and the method written calls that instance by name.

A trait stays where it is declared, which `docs/specs/modules.md` states, and a module offers no
trait of its own.
The prelude's are therefore the only traits two modules both name.
A constraint written over any other trait is answered by nothing here: this module cannot write
the instance, because it cannot write the trait's name.

```lumen
import holding

fn main(arguments: List<String>) -> Int {
    _ = holding.labelled(Kept("a"))
    0
}

type Kept = Kept(String)
```

`holding.labelled` is `fn labelled<T: Named<T>>(value: T) -> String`, and `Named` is a trait
`holding` declares.
`main` reaches `holding.labelled` and `holding.Kept` alike, because a module offers its functions
and its types, but it reaches no `Named`: an instance has no name to write, and neither has the
trait it would be written for.

Write the loop where the trait is:

```lumen
fn label_of(value: Kept) -> String {
    match value {
        Kept(word) => word
    }
}
```

Or call a generic whose constraint is one of the prelude's traits.
`Eq`, `Ord`, `Hash`, `Show`, and `IntegerLiteral` are in scope in every module alike, so a type
this module derives one of answers a constraint another module's generic writes over it.

```lumen
import list

if list.has_value([Kept("a")], Kept("a")) {
    io.println("kept")
}
```

A generic whose type parameters carry no constraint is reached at any type at all.
Nothing in such a body asks for an instance, so nothing has to be reached from the other module.
