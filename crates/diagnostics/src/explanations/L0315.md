# L0315 — a manifest is not written the way a manifest is written

A package is a directory of modules, and `bux.package` beside them is what names it.

```text
package shapes
version 0.2.0
depends ../geometry
```

Every line is a keyword, one space, and one word.
`package` is written first and `version` second, and a `depends` line for each dependency comes
after both.
There is one way to write a manifest, so a line out of that order, a keyword that is none of the
three, a missing word, a word holding a space, and a directory two `depends` both name are each
refused.

A path a `depends` states is read against the directory the manifest sits in, so `../geometry` is
that directory's sibling.
Nothing is fetched: the directory is already there, or `L0316` says it is not.

The name and the version are stated and nothing reads either yet, and a manifest that leaves one
out is refused all the same.
A package says what it is before anything asks, and the version that resolves is the version that
fetches.

`docs/specs/packages.md` states the manifest line by line.
