# L0428 — the signature names no class to reach

An `extern method` is called on a receiver, and an `extern new` builds what it gives back.

```text
extern method length(text: Int) -> Int = "length"

extern new counted() -> Int
```

Neither of these names a class.
A `method` states only the member, because the first parameter's type is what says which class
the member is on; a `new` states nothing at all, because its result is what says which class it
builds.
`Int` is a `long`, which has no members and no constructor, so neither declaration reaches
anything.

A class here is `String`, or a type an `extern type` declares.

```text
extern type File = "java.io.File"

extern method to_string(file: File) -> String = "toString"
extern new opened(name: String) -> File
```

A `method` that takes nothing is not written at all: `docs/specs/grammar.md` gives `extern method`
parameters rather than leaving them optional, so a receiver-less one is refused as a grammar is.

`field` and `static` are not refused for this, because each states its class in its own name.

`docs/specs/interop.md` states what each kind reaches and where it names the class it reaches it
on.
